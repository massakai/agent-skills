# Common Errors

## parse エラー

### ノードやエッジの構文崩れ

- 症状: 矢印や括弧の近くで parser が失敗する
- 対処: まず `A --> B` のような最小の有効エッジに戻し、その後でラベルを足し直す

### 危険または不整合な ID

- 症状: parse が失敗する、または後続参照が一致しない
- 対処: `service_api` のような単純な ASCII ID に正規化し、表示名はラベル側へ寄せる

### ラベルの引用ミス

- 症状: 記号、括弧、コロン付近で parser が失敗する
- 対処: 記号を明示的なラベルに移し、ノード ID は単純に保つ

### `subgraph` ブロックの不整合

- 症状: `subgraph` や `end` の近くで parse が失敗する
- 対処: すべての `subgraph` に対応する `end` があることを確認し、ラベルを単純化してから再検証する

## render エラー

### parse は通るのに renderer が失敗する

- 症状: レポートでparseは成功するがrenderが `kind: render` で失敗する
- 対処: 直前に追加した高度な構文を外し、`parse` から再開する

### 未対応または壊れやすいスタイル指定

- 症状: 複雑なスタイルや class 追加後に render が失敗する
- 対処: `classDef`、インライン style、theme 設定を一度外し、まず素の図を描画させる

### レイアウト破綻

- 症状: render は通るが図が崩れる、極端に読みにくい
- 対処: ラベルを短くする、交差を減らす、複数図へ分割する

## 復旧パターン

`kind: environment`（ブラウザ起動、権限、依存、出力先）の場合は、下記の構文縮小を行わず環境を修復する。ソース不変なら `--resume` で成功済みparseを再利用できる。権限エラーの対応は [SKILL.md](../SKILL.md) を参照。

1. 図に原因がある場合は、失敗する最小例まで縮める。復旧の土台が必要なら [diagram-patterns.md](diagram-patterns.md) の図種別ごとの最小例を使う
2. ソース修正後は `parse` から検証し、失敗した図は修正して再検証する
3. `parse` 成功後に `render` と目視確認を行う。問題があれば修正して手順2へ戻る
4. 詳細は一段ずつ戻し、その都度手順2〜3を繰り返す。元の要件を満たす図に戻すまで、縮小した例だけで完了扱いにしない
