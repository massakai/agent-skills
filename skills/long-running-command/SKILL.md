# 長時間コマンドの待機

対象・保存先を確認し、一度起動し、同じ処理の終了を待ち、終了結果を確認してから必要な結果照合へ進む。
このスキルはコマンド実行の承認や、実キー・本番操作・課金の許可を追加しない。
常駐サーバーや入力待ちの対話コマンドには使わない。

## 起動と待機

1. コマンド、対象checkout、CIならPR・head・run IDを確認する。
   認証確認は既存のGitHub手順に従う。
2. 保存する内容と利用条件を確認し、対象リポジトリ内のGit除外された保存先を使う。
   `git check-ignore tmp/command-wait/`などで保存前に除外を確認する。
3. [補助スクリプト](scripts/run_and_wait.py)を使い、コマンドを一度だけ起動する。
   スクリプトの位置は読み込んだスキルのディレクトリから解決する。
4. ツールが実行中セッションを返した場合は、同じセッションの終了を待つ。
   ツールの仕様に従い、利用可能な範囲で最大60秒の待機を指定する。
   外側の実行セルが継続中ならそのセルを待ち、内側の処理を二重に待機・起動しない。
5. 終了時のJSONとツールの終了コードを確認し、必要な結果照合を行う。
   実行中のログ取得、`tail`、プロセス状態やCIへの別照会、短時間待機を進捗目的で追加しない。

無出力・経過時間・CPU使用率だけを理由に診断、停止、再実行しない。
同じ状態の途中報告は行わず、上位指示で定期連絡が必要な場合も追加照会せず待機継続の事実だけを伝える。
ユーザーが状況確認・中断を指示した場合や、明示的なツールエラーが返った場合は対応する。
ツールのタイムアウトはコマンドの失敗や停止完了と同一視せず、既存セッションを確認してから判断する。

```sh
python3 <スキルディレクトリ>/scripts/run_and_wait.py --log-dir tmp/command-wait -- uv run --locked pytest
python3 <スキルディレクトリ>/scripts/run_and_wait.py --log-dir tmp/command-wait -- gh run watch <run-id> --repo example-org/example-repo --exit-status --compact --interval 60
```

`<スキルディレクトリ>`と`<run-id>`は実行前に解決するプレースホルダーである。
シェルの展開が必要な引数は呼び出し側で解決し、スクリプトは渡された引数配列をシェルへ再解釈させない。

## 終了結果の契約

Python 3.10以降のmacOS/Linuxで使う。
標準出力・標準エラーは実行ごとの`command.log`へまとめて保存し、終了時だけ標準出力へJSONを一行返す。
引数不正や非対応OSは起動前のCLIエラーとして標準エラーへ返す。
既存ログを上書きせず、ログと実行ディレクトリは所有者のみ読み書きできる権限で新規作成する。
コマンド引数・環境変数は結果JSONへ記録しない。
ログは秘密情報を含む可能性があるため、公開・コミットせず内容を確認して扱う。

| フィールド | 意味 |
| --- | --- |
| `status` | `success`、`failed`、`start_failed`、`interrupted` |
| `exit_code` | ラッパーの終了コード。通常の非0終了を保持し、シグナル終了は128+シグナル番号に変換する |
| `returncode` | 子プロセスの終了コード。シグナル終了は負の番号、起動失敗は127または126 |
| `elapsed_seconds` | 起動準備から終了までの単調時計による所要秒数 |
| `log_path` | 保存先。相対指定なら実行checkoutからの相対パス、作成前の失敗なら`null` |
| `error` | 起動失敗時の例外型名、それ以外は`null` |

SIGINT/SIGTERMを受けた場合は子のプロセスグループへ転送して子の終了を待つ。
中断を処理した子が0で終了しても、`interrupted`として非0終了を返す。
シグナルを無視する子を自動で強制終了せず、追加の停止指示に従う。
SIGKILLや実行ホストの停止では終了JSONを保証できず、停止完了の証拠とは扱わない。
コマンドの自動再試行や、無出力を理由とする時間制限は追加しない。

## CIの終了後の照合

CLI内部の`--interval 60`はGitHubへの照会間隔であり、エージェントが途中ログを読む間隔ではない。
watchの終了後にPRの最新headとチェック一覧を読み戻す。
run IDを指定した場合は、そのrunのhead SHAと全jobの結論も確認する。
headが変わった場合は古いrunを合格証拠にせず、最新headを対象に同じ手順を開始する。
必須チェックに未完了が残る場合は`pending`、failure・cancelled・未確認はその状態を保持する。
対象headの必須チェックがすべて成功した場合だけCIを`success`とする。
監視の通信・認証エラーをCIの失敗と同一視しない。
失敗ログの解析は終了後に行い、PR公開・ローカル検証・CIの結果を分けて報告する。

## 検証

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s skills/long-running-command/tests -v
```

合成コマンドだけで終了結果、無出力、ログ保存、中断を検査する。
新しいチャットでの行動確認には[合成CIシナリオ](tests/fake_gh.py)を使う。
補助スクリプトは中間出力を抑制するが、エージェントの全操作を強制禁止するものではないため、実行履歴も確認する。
