# Git commit

ローカルの変更を commit する依頼で使う。複数リポジトリで再利用できる commit の判断規則を扱う。

push、PR、GitHub 認証、CI の待機・判定、merge、履歴書換えは扱わない。

## Commit 前

1. 対象リポジトリの `AGENTS.md`、コミット文面規約、必要な検証を確認する。
   ユーザーが対象ファイルやコミット分割を指定していれば、それを優先する。
2. `git status`、未 stage の diff、stage 済み diff を確認する。
   対象外の変更、既存の stage、未追跡・ignored ファイルを自動でまとめない。
3. 一つの commit は、一つのレビュー可能な意図にする。
   独立して理解・検証・revert できない変更が混在する場合は、ファイルまたは hunk を分ける。
   分割の判断が曖昧で結果を大きく変える場合は、commit 前に方針を確認する。
4. stage は、明示されたリポジトリ相対パスまたは確認済み hunk に限定する。
   ディレクトリ・ワイルドカード・全変更の一括 stage を、対象確認の代わりに使わない。
5. commit に含める差分と必要なローカル検証を再確認する。
   未実行の検証を成功と表現せず、秘密情報、生成物、意図しないローカル設定を commit しない。

## Commit

- リポジトリの文面規約を優先する。規約がなければ、変更の内容を簡潔に表すメッセージを使う。
- AI エージェントが変更に関与した commit には、対象リポジトリの規約と利用者の指定を優先して `Co-authored-by` トレーラーを付ける。
  指定がなければ、実際に作業したエージェントを共同作成者として記す。
  名前とメールアドレスは、提供元の公開資料または導入先の規約で確認し、推測しない。
  Codex で別の指定がなければ、OpenAI の[公開スキルの例](https://github.com/openai/symphony/blob/main/.codex/skills/commit/SKILL.md)にある `Co-authored-by: Codex <codex@openai.com>` を使う。
  本文との間に空行を置き、同じトレーラーを重複させない。
  他のエージェントへ Codex の識別子を転用しない。確認できる識別子がなければトレーラーを付けず、その理由を報告する。
- 推測した Issue 番号、検証結果、破壊的変更を本文に補わない。
- commit は、ユーザーが依頼または承認した変更範囲だけで行う。
- 失敗や結果不明時は、同じ commit を推測で再実行せず、HEAD と stage 状態を確認する。

## Commit 後

- commit SHA、件名、含めたパス、残った変更、実行済み検証を別々に報告する。
- push、PR 作成・更新、GitHub Issue/Project 更新、merge は範囲外である。
  必要なら、それらを扱う別の手順へ進む。
