# コストを意識した委譲

この skill は、複数エージェントで作業を分担するときの計画と引き継ぎに使う。目的は、親エージェントが最終判断と統合を保ちつつ、独立した作業を安全に並列化することである。

## 委譲前に固定すること

親エージェントは、子エージェントごとに次を明記する。

- 正確な操作、対象パス、成果物、完了条件
- 読み取り専用か、編集可能か、外部への書き込みを含むか
- 依存する前提と、作業を止めて親へ返す条件
- 実行する検査と報告形式
- 共有 worktree や共有 Git ディレクトリでの同時書き込みを避ける方法

一つのファイルまたは共有状態を同時に書く担当者は一人にする。依存関係がある作業は、先行作業の結果を確認してから委譲する。

## モデルと作業粒度

- まず決定的なスクリプトや検査を実行し、その出力を使える独立作業として切り出す。
- 抽出結果の整理、定型的な下書き、単純な検査、親が確定した更新操作は `gpt-5.6-luna` / `low` を使う。
- PRコメントの一覧化と返信下書きは、この定型作業に含める。「レビュー」という名前だけで上位モデルへ変更しない。
- 複数文書の整合や追加の判断を伴う照合は `gpt-5.6-terra` / `medium` を使う。
- 安全性、権限、公開、実運用などの複雑な判断は親エージェントが保持する。

モデル名や reasoning effort を指定できる場合は、両方を明示する。fork は `fork_turns=none`（または必要最小限）にし、既存の有用な親作業と並行できる独立した仕事を委譲する。単純な一行コマンドだけを委譲するためにエージェントを増やさない。モデルが利用できない、または実行に失敗した場合は親へ報告し、同じ条件で再試行を繰り返さない。

委譲の速度やコストは環境で変わるため、性能を測定していない限り、固定の秒数・トークン数・節約率を主張しない。

これらのモデルが利用可能な環境で適用し、親の既定設定を一括変更しない。選択の背景は[公式サブエージェント資料](https://learn.chatgpt.com/docs/agent-configuration/subagents)を参照する。実行後は手戻り、親が読み直した範囲、取得可能なトークン量を確認する。取得できない指標は未測定とする。

子エージェントには必要最小限の文脈だけを渡す。独立レビューでは答えや疑わしい結論を先に与えず、確定済み操作の委任では対象と手順を具体的に渡す。新しい外部権限、資格情報、課金、実注文を委譲によって得たものとして扱わない。

## 再試行と完了報告

同じ入力での反復再試行は、原因を変えずにコストと副作用だけを増やす。失敗時はログ、失敗地点、次に必要な判断を一度報告し、親が方針を決める。子エージェントは、変更したパス、実行した検査、未解決事項を簡潔に返す。
